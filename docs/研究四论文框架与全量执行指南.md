# 研究四：面向真实市场的策略自进化交易框架

## 一、研究背景

传统量化策略通常在固定规则、固定因子和固定参数下运行。市场状态发生变化后，策略可能出现收益衰减、风险暴露失控和回撤扩大等问题。大语言模型能够读取价格、新闻和程序化分析结果，但仅依靠提示词生成交易建议仍然存在三个不足：决策过程难以持续更新，策略失效缺少明确触发标准，历史调整经验难以形成可验证的累积知识。

本研究关注的问题不是让模型一次性给出更复杂的交易指令，而是构建一个能够在真实市场时间轴上持续观察、检测失效、选择调整方向、验证更新并在无效时回滚的策略自进化框架。

## 二、研究缺口

现有研究主要存在以下缺口：

1. 许多LLM交易研究停留在单次决策或提示词比较，缺少跨时间的策略更新机制。
2. 现有进化式交易框架通常报告最终收益，但没有把失效触发、更新准入、回滚和交易成本放在同一可复现实验协议中。
3. 策略更新容易把未来信息、事后解释或样本内调参混入决策过程，样本外有效性不足。
4. 研究往往只比较一个改进方法和一个基线，无法区分情景识别、杠杆调整、经验利用和真正的自进化贡献。
5. 结果展示缺少从单次决策记录到长期净值、更新间隔、交易成本和异质市场验证的完整链条。

## 三、研究问题

**RQ1：** 在真实市场数据和工具调用约束下，LLM是否能够稳定完成可审计的交易决策？

**RQ2：** 明确的策略失效检测和情景条件经验门控，能否改善固定策略的风险收益表现？

**RQ3：** 策略自进化的增益来自情景识别、风险调整、经验利用还是它们的组合？

**RQ4：** 自进化机制在不同市场窗口、更新间隔、交易成本和长期样本外区间下是否稳健？

**RQ5：** 在A股真实市场环境中，基于美股实验得到的自进化流程是否具有可迁移性？

## 四、核心设计

### 4.1 时间因果约束

在决策日 (t)，策略只能使用截至 (t) 已知的价格、成交量、新闻和工具结果；收益在 (t+1) 之后实现。财务信息和新闻信息必须使用可获得日期，而不是事后报告日期。所有更新、经验记录和回滚判断都写入时间戳。

### 4.2 基线策略

基线包括固定规则策略、固定工具调用策略、静态LLM策略和原始EvolveTrade策略。每个实验单元使用相同资产池、价格区间、交易成本、最大资产权重和现金约束。

### 4.3 创新策略

创新策略由五个模块组成：

1. **市场情景识别**：根据市场动量和历史波动率划分上涨/下跌与高波动/低波动状态。
2. **失效检测**：依据滚动收益、策略回撤和近期表现识别当前策略是否失效。
3. **经验门控**：仅从过去同类情景的已实现结果中选择候选调整，不使用未来结果。
4. **更新准入与回滚**：候选调整必须通过历史经验门槛；若更新后表现劣于原策略，则恢复基础暴露。
5. **风险与成本约束**：所有调整都受资产权重上限、换手成本和风险暴露约束。

其核心形式可以表示为：

\[
s_t = g(M_t, V_t),\qquad
I_t = \mathbb{1}(R_{t-k:t}<\tau_R \;\lor\; DD_t<\tau_D),
\]

\[
a_t = \arg\max_{a\in\mathcal{A}}\widehat{E}[R(a)\mid s_t,\mathcal{H}_{t-1}],
\qquad
w_t = \Pi_{\mathcal{C}}(a_t w_t^{base}),
\]

其中 (s_t) 为市场情景，(I_t) 为失效触发器，(mathcal{H}_{t-1}) 为历史经验，(Pi_{\mathcal{C}}) 为权重、成本和风险约束投影。

### 4.4 对照与消融

正式创新测试必须同时包含：Baseline、ScenarioOnly、ExperienceOnly、FixedLeverage、ContextEvolution。FixedLeverage用于识别收益提升是否仅来自提高风险暴露；其余消融用于分解各模块的边际贡献。

## 五、系统架构

```text
真实市场数据与新闻
        |
        v
数据审计与时间因果检查
        |
        +--> 固定规则/静态策略基线
        |
        +--> 工具调用与DeepSeek决策层
                    |
                    v
             策略反馈记录器
                    |
                    v
             情景识别与失效检测
                    |
                    v
             经验门控与候选更新
                    |
                    v
              OOS准入与回滚
                    |
                    v
             净收益、风险、成本
                    |
                    v
        表格、图形、显著性与论文结果
```

## 六、实验层级

### 层1：数据与代码自检

运行真实数据质量检查、字段检查、日期连续性检查、缺失值检查、重复键检查和脚本语法检查。

### 层2：完整创新冒烟

冒烟样本较短，但执行完整流程：数据审计、基线、创新策略、控制组、消融、成本、滚动样本外、Bootstrap、显著性、7张表和图形输出。冒烟测试只验证系统功能与流程闭环，不作为最终论文的长样本结论。

### 层3：正式主矩阵

正式主矩阵使用6个市场窗口、5种方法和3个seed，共90个实验单元，并从 `result/runs` 断点恢复。每个单元都保留逐日记录、工具轨迹、策略版本、指标和检查点。

### 层4：稳健性与拓展

依次执行更新间隔敏感性、长期实验、交易成本比较、论文表格、论文图形和A股验证。

## 七、云端全量执行步骤

### 步骤1：环境与数据检查

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m compileall src coding
python coding/3_validate_real_data.py
```

必须确认使用 `data/real/` 中的真实价格、OHLCV和新闻数据，不使用demo数据、合成数据或模拟代理。

### 步骤2：运行完整创新冒烟

```bash
python coding/15_innovation_full_smoke.py
```

输出目录为 `result/innovation_full_smoke/`。该步骤必须先于正式长样本矩阵执行，用于验证所有函数、表格、图形和统计检验均可运行。

### 步骤3：启动正式主矩阵

```bash
python coding/5_run_llm_experiments.py
```

只能启动一个主矩阵进程。程序按窗口、方法和seed写入结果，并从已有 `records.jsonl`、`metrics.csv`和`tool_checkpoint_*.json`继续恢复。

### 步骤4：执行正式后处理

```bash
python coding/6_run_interval_sensitivity.py
python coding/7_run_long_horizon.py
python coding/8_generate_paper_tables.py
python coding/9_generate_paper_figures.py
python coding/11_run_a_share_validation.py
python coding/13_generate_a_share_results.py
```

### 步骤5：结果完整性核验

必须核验：6个市场窗口、3个seed、表1至表7、图2至图7、交易成本、长期实验、更新间隔敏感性和A股结果是否全部存在。任何单元缺少逐日记录、指标或图表时，不得进入论文定稿。

## 八、进度显示规范

全量运行必须显示三个层级的进度：

```text
主矩阵: [完成单元/总单元] [完成百分比] 当前窗口/方法/seed
当前单元: [已完成决策日/总决策日] [完成百分比] 最近更新时间
后处理: [已完成阶段/总阶段] 当前阶段名称
```

建议将标准输出和错误输出分别保存，同时每个实验单元写入 `status.json`。进度只能根据已落盘的记录计算，不能根据预计时间伪造。断点恢复后先扫描已有结果，再继续缺失单元。

## 九、论文结果组织

论文结果章节按以下顺序展开：

1. 数据与实验协议；
2. 基线复现结果；
3. 创新冒烟流程验证；
4. 主矩阵表现比较；
5. 因子与模块消融；
6. 交易成本和更新间隔敏感性；
7. 长期样本外结果；
8. 异质市场与A股验证；
9. 失败案例、回滚案例与边界条件；
10. 统计显著性和稳健性结论。

所有结论必须与实际生成的表格和图形一致。冒烟结果只能作为流程可行性证据，最终创新结论必须依据完整样本、样本外区间、统一成本口径和显著性检验。
